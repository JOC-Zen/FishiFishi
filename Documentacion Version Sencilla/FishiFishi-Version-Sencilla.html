1. Resumen Ejecutivo

La version sencilla de FishiFishi es una plataforma B2B mayorista para vender pescados y mariscos a empresas. Su objetivo no es automatizar toda la operacion internacional desde el inicio, sino ordenar el proceso comercial: registro de compradores, catalogo, solicitudes de cotizacion, pagos confirmados, seguimiento de entrega y confirmacion de recibido.

El equipo FishiFishi conserva el control sobre precio final, disponibilidad, impuestos, logistica y condiciones de entrega. La plataforma sirve como sistema comercial y operativo para reducir desorden, evitar riesgos de impago y dar trazabilidad al comprador.

Regla central: no se libera mercancia sin pago confirmado, preautorizacion valida o garantia capturada. No se recomienda operar con notas de credito, credito abierto ni promesas de pago como base del modelo.

2. Alcance De La Version Sencilla

Incluye

  • Registro de clientes empresariales.
  • Catalogo mayorista.
  • Solicitud de cotizacion.
  • Solicitud de compra programada.
  • Pago por tarjeta, WeChat Pay y cripto/stablecoins.
  • Panel administrativo.
  • Seguimiento tipo DiDi.
  • Confirmacion de recibido por comprador.
  • Estadisticas basicas.

No Incluye Al Inicio

  • Calculo automatico avanzado de impuestos por pais.
  • Motor aduanal automatizado.
  • Integracion completa con navieras y paqueterias.
  • Credito abierto para compradores.
  • ERP completo.
  • Marketplace con multiples vendedores.

3. Arquitectura Recomendada

Se recomienda una arquitectura modular monolitica para el MVP. Esto permite avanzar rapido, mantener el codigo ordenado y evitar complejidad innecesaria de microservicios desde la primera version.

Capa Responsabilidad Tecnologia Recomendada
Frontend Interfaz del comprador y panel administrativo. Next.js, React, TypeScript, Tailwind CSS o CSS Modules.
Backend Logica de negocio, ordenes, pagos, cotizaciones y permisos. NestJS con TypeScript o Laravel con PHP.
Base de datos Clientes, productos, solicitudes, ordenes, pagos y estados. PostgreSQL.
Archivos Facturas, documentos, comprobantes y evidencia de entrega. Amazon S3, Cloudflare R2 o storage compatible S3.
Pagos Tarjetas, WeChat Pay y cripto/stablecoins. Stripe, proveedor WeChat Pay, proveedor cripto regulado.
Notificaciones Alertas de estado, pago y recibido. Email, WhatsApp Business API, WeChat notifications.
Infraestructura Hosting, despliegue y monitoreo. Vercel/Cloudflare para frontend, Render/Fly/AWS para backend.

5. Modulos Funcionales

Clientes Empresariales

Registro de razon social, pais, datos fiscales, contacto de compras, contacto financiero, contacto autorizado para confirmar recibido y metodo de pago preferido.

Catalogo Mayorista

Productos con presentacion, unidad de venta, volumen minimo, temporada, disponibilidad, ficha tecnica y boton de solicitar cotizacion.

Cotizaciones

El comprador envia cantidad, destino, fecha deseada y comentarios. El equipo FishiFishi revisa costos reales y genera una cotizacion personalizada.

Pago Asegurado

Modulo central para generar links de pago, confirmar pagos, detectar pagos fallidos y bloquear ordenes sin pago confirmado.

Ordenes

Convierte cotizaciones aceptadas en ordenes. Controla estados desde pago pendiente hasta recibido confirmado.

Seguimiento Tipo DiDi

Permite al comprador ver avance, recibir notificaciones, confirmar recibido y reportar incidencias con evidencia.

Panel Administrativo

Permite aprobar compradores, crear cotizaciones, cambiar estados, registrar pagos, subir documentos y gestionar incidencias.

Estadisticas Basicas

Volumen solicitado, volumen comprado, pagos fallidos, ordenes cerradas, incidencias y productos con mayor demanda.

6. Flujos Principales

Compra simple

  1. El comprador se registra como empresa.
  2. FishiFishi valida o aprueba la cuenta.
  3. El comprador selecciona producto y solicita cotizacion.
  4. FishiFishi revisa costos reales y envia cotizacion.
  5. El comprador acepta la cotizacion.
  6. La plataforma genera link de pago.
  7. El comprador paga con tarjeta, WeChat Pay o cripto/stablecoin.
  8. El sistema confirma el pago.
  9. FishiFishi prepara y envia la mercancia.
  10. El comprador confirma recibido o reporta incidencia.

Compra programada simple

  1. El comprador solicita volumen total, fechas y frecuencia de entregas.
  2. FishiFishi revisa disponibilidad y condiciones.
  3. Se genera una cotizacion o contrato manual.
  4. Cada entrega queda como orden parcial.
  5. La orden parcial solo se libera con pago confirmado o garantia capturada.
  6. El comprador confirma recibido por cada entrega.

7. Requerimientos Funcionales

ID Requerimiento Prioridad

RF-09 El sistema debe mostrar estadisticas basicas por comprador y producto. Media

8. Requerimientos No Funcionales

Seguridad

  • Autenticacion con roles.
  • Contrasenas hasheadas.
  • 2FA para administradores.
  • No almacenar tarjetas directamente.
  • Uso de proveedores tokenizados.

Pagos

  • Confirmacion mediante webhooks.
  • Registro de eventos de pago.
  • Estados claros: pendiente, confirmado, fallido, reembolsado.
  • Bloqueo automatico de orden sin pago.

Escalabilidad

  • Arquitectura modular.
  • Base de datos relacional.
  • Separacion entre frontend, backend y storage.
  • Preparado para integraciones futuras.

Compatibilidad Internacional

  • Multidioma desde el inicio.
  • Multi moneda desde modelo de datos.
  • Evitar dependencias bloqueadas en China.
  • Soporte futuro para chino simplificado.

11. Recomendacion Tecnica

Para la primera version, se recomienda construir FishiFishi como un monolito modular con frontend moderno y backend API. La prioridad debe ser tener un flujo comercial completo y seguro antes de automatizar calculos complejos.

La plataforma debe quedar preparada para crecer, pero sin cargar al MVP con integraciones que todavia pueden resolverse manualmente por el equipo. El diferenciador real desde la primera version debe ser la disciplina operativa: pago confirmado, estado visible, evidencia, recibido confirmado e historial por comprador.
